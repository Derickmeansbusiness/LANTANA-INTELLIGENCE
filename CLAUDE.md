## Non-negotiables
- Build phase by phase (PLAN.md §9). Each phase must pass typecheck, lint, pgTAP RLS tests and the Playwright click-through (375px + desktop, light + dark) before the next one starts.
- RLS is the security boundary. Never use the service-role key in a user request path. That includes the public share page: it runs as `anon` and reads the file through the storage policy `lantana_docs_share_read` (see Conventions).
- Sensitive data (compensation, bank accounts, ID numbers) lives in separate principal-only tables, pgcrypto-encrypted, with the key in Supabase Vault (`private.pii_key()`).
- All business logic goes in `src/server/<module>`. Server actions and agent tools both call it.
- Agent write tools create `agent_actions` proposals. They execute only on user confirmation, re-checking permissions. There is no delete tool.
- Money is `bigint` minor units + ISO currency. Use `src/lib/money.ts`. XAF has 0 decimals.
- All dates and crons run on Asia/Dubai (UTC+4, no DST). Use `src/lib/dates.ts` / `private.today_dubai()`.
- Migrations are additive. Ask before anything that drops or rewrites data, and before adding any paid service.
- No lorem ipsum. Seed rows carry `is_demo = true`.
- Don't put model identifiers in commits or code comments. The model comes from `ANTHROPIC_MODEL`.

## Conventions
- **DB:** helpers live in the `private` schema (not exposed). Every business table has `is_demo`, `created_by default auth.uid()`, `deleted_at`, an `audit_row()` trigger and RLS. No DELETE policies on business records. The exceptions are link/preference rows (`deal_members`, `deal_parties`, `task_dependencies`, `task_checklist_items`, `saved_views`), which are still audited. SELECT policies don't filter `deleted_at` (that breaks `UPDATE … RETURNING` on soft delete), so queries and views filter it. `private.guard_archive()` stops anyone below manager from setting `deleted_at` (task/comment/note/interaction creators may archive their own).
- **Domain layer:** `src/server/{deals,partners,relationships,tasks,ledger}.ts` take the caller's `Db` client and return `ActionResult` (`src/lib/action-result.ts`). `src/server/actions/*` are thin `"use server"` wrappers that add `revalidatePath`. Zod schemas in `src/lib/schemas/*` are shared by forms and the server.
- **PostgREST embeds:** hint with the FK constraint name (`profiles!deals_owner_id_fkey`), except self-references, which embed by column (`corrected:corrects_id(seq)`).
- **Roles:** `private.is_principal()` = role principal AND (aal2 OR `company.require_principal_mfa` false). A principal at aal1 gets manager-level access. `private.is_manager_plus()`, `private.is_internal()`, `private.can_see_deal()`, `private.can_see_org()`, `private.can_see_document()`, `private.can_write_document()`.
- **RLS policies must read the row's own columns**, not re-query the table by id: a re-query can't see the row during `INSERT … RETURNING`. `doc_read` uses `private.doc_visible(id, confidentiality, created_by)` for this reason (pgTAP covers it).
- **Documents:** visible to manager+; to anyone internal if public/internal; to the uploader; and to staff for non-restricted files linked to a deal they're on. Storage path is `<document_id>/<random uuid>/<safe file name>`; storage policies mirror the table (`lantana_docs_read/insert`). Stored versions are immutable (no update/delete policies). `version_no` is assigned by the database. Upload goes browser → storage under the user's session → `registerVersionAction` → ingestion in `after()` with the same user's token (`createTokenClient`). `document_chunks` is derived data and may be deleted and rebuilt.
- **Share links:** only the sha256 of the token is stored; the token is shown once. `/s/<token>` is public (listed in `proxy.ts`), calls `open_share_link()` as `anon` (logs every attempt, bumps the view count), then reads the object through `lantana_docs_share_read`. That policy opens for 2 minutes after a logged successful view of that exact path, and closes on revoke. Only PDFs and PNG/JPEG can be shared, because only those are watermarked (pdf-lib, `src/server/documents/watermark.ts`). `anon` has `usage` on schema `private` for this one function, so **every migration must end with `revoke execute on all functions in schema private from public, anon`** and re-grant `private.share_object_open` to anon if it recreates it.
- **Templates:** the catalog is pure data + `build()` in `src/lib/templates/catalog.ts` (unit-tested). It produces blocks (`src/lib/templates/types.ts`) that `src/server/templates/render-pdf.tsx` and `render-docx.ts` render. Output is saved into the vault as a draft document. In react-pdf, give any text with `lineHeight` an explicit `fontSize`: a unitless lineHeight resolves against the 18pt default, not the inherited size.
- **Contracts** are manager+ (RLS); the pages return not-found for staff. `src/lib/contract-dates.ts` computes the key dates the UI shows; `private.run_expiry_alerts()` (pg_cron, 03:15 UTC = 07:15 Dubai) is the source of truth for alerts, one per threshold band per target date (`alerts_sent`). A dated obligation creates a task (trigger `obligations_to_task`); closing or waiving the obligation closes or cancels the task.
- **Ask Lantana** (`src/server/agent/*`): `tools.ts` defines each tool once (Zod → JSON Schema via `z.toJSONSchema(…, { io: "input" })`, stable order so the prompt caches). Read tools run under the user's JWT and pass through `redact()`. Write tools only `propose()`: they insert an `agent_actions` row and the UI shows a card; `confirmProposal()` executes it later through the same domain function the UI uses, under the confirming user's JWT, so permissions are re-checked (proposals expire after 24 h; a trigger allows exactly one decision and no edits). There is no delete or send tool. `run.ts` is a manual streaming loop (`client.beta.messages.stream` + `finalMessage()`): it stores every turn's content exactly as received and replays it unchanged (thinking blocks included), applies the fallback echo rule (`echoable()`), runs only tool calls after the last `fallback` block, never runs tools from a `max_tokens` or `refusal` turn, and caps tool rounds at 8. Per-turn context (who, page, record, Dubai time, decisions on earlier proposals) goes in the user turn, never the system prompt, so the cached prefix stays valid. Document text reaches the model inside `<document>` tags as untrusted data.
- **Agent tables:** threads and messages are private to their owner (no one else, principals included); `agent_actions` and `agent_usage` are readable by their owner and by principals. Messages aren't audited row by row; actions and clause reviews are.
- **Finance** (`src/server/finance.ts`, pure helpers in `src/lib/finance.ts`): ledger, invoices, bills, budgets and rules are manager+. Amounts convert to AED at each row's date (`aedRates`, `private.convert_major`); rows without a rate are counted and reported, never guessed. `finance_monthly()` is definer (manager+) so the P&L includes payroll in aggregate; `finance_cash_monthly()` returns nothing to non-principals. Statement import: parse → `suggest_transaction_categories()` (longest rule, else most similar past line by trigram) → a person reviews every line → insert with `import_hash` (sha256 of bank|currency|date|amount|description|occurrence), so re-importing skips duplicates. Issued invoices are frozen by `private.invoice_guard()`; draft totals follow `invoice_items` + VAT. Paying an invoice or bill writes the ledger line.
- **People** (`src/server/people.ts`, `src/lib/people.ts`): `employees` is manager+ plus each person's own row; everyone internal gets `people_directory()`. `employee_identity`, `employee_compensation`, `payroll_runs`, `payroll_items` are principal-read-only and **nobody can write them directly** (grants revoked): `set_employee_identity`, `add_employee_compensation`, `create_payroll_run`, `update_payroll_item`, `set_payroll_status`, `set_payroll_wps` validate and encrypt with `private.enc()`. Reads in clear go through `reveal_employee_identity`, `employee_compensation_history`, `payroll_run_detail`, `payroll_wps_data`, `salary_certificate_data`, which each write a `reveal` audit row; the UI calls them only on an explicit click. Leave: staff request/cancel their own (`private.leave_guard()`), manager+ decide, nobody decides their own unless principal. Rows hanging off an employee inherit its `is_demo` (`private.inherit_demo()`).
- **Compliance** (`src/server/compliance.ts`): `private.compliance_guard()` lets only a principal move an item out of `unconfirmed` (or create one confirmed) and stamps `confirmed_by/at`; completing a recurring item inserts the next one. Corporate records and staff document expiries feed `run_expiry_alerts()` and the attention queue.
- **Views/RPCs** used by the UI are `security_invoker`, so they return only what the caller may see. The exceptions (`SECURITY DEFINER`, callable by signed-in users) check the role themselves: `log_event`, `set_user_role`, `wipe_demo_data`, `set/reveal_bank_account_iban`, `run_expiry_alerts_now`, `run_nightly_scan_now`, `verify_introductions_chain`, `private.kpi_burn_aed`, `finance_monthly`, `people_directory`, the people/payroll functions listed above, and from Phase 6 `portal_room_documents`, `open_room_document`, `log_room_open` (membership-checked) and `log_export` (principal). `private.enc/dec/dec_minor` and `private.pii_key` are revoked from `authenticated`; keep them that way. `open_share_link` is also callable by `anon` (the token is the credential). The Supabase advisor flags these; that's expected.
- **Seeds/imports** can backdate events with `set_config('app.occurred_at', …)`; `private.event_time()` reads it.
- **UI:** shadcn-style components are hand-written in `src/components/ui` (the shadcn registry is blocked from this container). Tokens are in `src/app/globals.css`. Gold is an accent only. Use the `num` utility for money and dates. Grid children need `min-w-0` (Card has it by default) or long text blows out mobile layouts.
- **Module sub-pages** use `SectionTabs` (`src/components/section-tabs.tsx`) under one `PageHeader` in the module's `layout.tsx` (Finance, People, Compliance). Pages under a manager+ layout call `notFound()` for staff from the layout.
- **Charts:** two-series charts use `--chart-in` / `--chart-out` (validated for colour-blind separation and contrast in both themes); no dual axes. Closing cash sits under the cash-flow chart as numbers, not a second axis.
- **Records:** any record opens in the side sheet via `?record=<type>:<uuid>` (`src/components/shell/record-sheet.tsx`). Tasks open the editable `TaskSheet` via `?task=<uuid>` (or `?record=task:<uuid>`). Deals, organizations, documents and contracts have full pages.
- **Tables:** use `src/components/data-table/data-table.tsx` (TanStack Table **v8**, pinned; v9 has a different API). It gives search, facets, sorting, column visibility, saved views and CSV export (UTF-8 BOM, formula-injection safe).
- **PDFs:** `@react-pdf/renderer`, letterhead in `src/server/pdf/letterhead.tsx`. Standard fonts only draw WinAnsi characters, so pass text through `pdfText()`. Hyphenation is off.
- **Not found:** `src/app/(app)/not-found.tsx` covers both "doesn't exist" and "RLS hides it" on purpose. Status is 200 because `loading.tsx` starts streaming first; tests assert on content.
- **Server actions:** `"use server"` files may only export async functions. Shared types go in a sibling module (e.g. `src/server/records-shared.ts`).
- **Client/server boundary:** a server page can't call a function exported from a `"use client"` module (it gets a client reference). Put shared helpers in a plain module (`src/components/documents/format.ts`, `src/components/contracts/format.ts`).
- **Next.js 16:** `proxy.ts` (not middleware), async `params`/`searchParams`/`cookies()`. Bundled docs are in `node_modules/next/dist/docs/`.
- **Accounts are invite-only, enforced in the database.** `private.handle_new_user()` refuses an `auth.users` insert unless it finds an open `user_invites` row, a role in `app_metadata`, or `invited_at` (a dashboard invite). Sign-up is therefore ON in Supabase Auth and the login action uses `shouldCreateUser: true`. Principals invite any role; managers invite `external` only (`private.can_invite`). An invite's email and role can't change after it is made (`private.invite_guard`).
- **External guests** (role `external`) are redirected from the `(app)` layout to `/portal` (`src/app/portal/*`, its own shell). Route handlers skip layouts, so any handler that could serve a guest checks the role itself (`/api/agent`, `/deals/ledger/export`, `/reports/pdf`, `/settings/export`). RLS gives a guest only their own profile, their rooms and their memberships.
- **Data rooms** (`src/server/data-rooms.ts`, `/data-rooms`, manager+): files from the vault (PDF/PNG/JPEG only, `private.room_document_guard`), guests by email (an existing colleague is refused; a new address gets an external invite; `private.room_members_claim` links the membership on sign-up), open/closed plus expiry, view-only or download. A guest opens a file through `/portal/<room>/file/<doc>`. That calls `open_room_document()` (checks membership, logs a `data_room_events` row), then downloads under the guest's own session through storage policy `lantana_docs_room_read` (open for 2 minutes after a logged view of that exact path), then watermarks with the guest's email and the time. Guests can't write events (no grant).
- **Reports** (`src/lib/reports.ts` catalog, `src/server/reports.ts`): every section is computed under the reader's JWT by the same domain functions the module pages use. Cash is built only for an MFA-verified principal (`PRINCIPAL_ONLY`) and is never written to a vault copy, because managers can open the vault. Download (`/reports/pdf`) is built fresh, may include cash, is audited, and is logged in `report_runs` with no document. Schedules: `private.run_report_schedules()` (pg_cron 03:30 UTC = 07:30 Dubai; weekly on Mondays, monthly on the 1st) only notifies recipients (`report_due` → `/reports/view?schedule=`); the PDF is built when they open it. No email until a provider is approved. Link to a route handler with a plain `<a download>`, never `<Link>`: client navigation to a handler moves the page URL, and later server actions then POST to the handler (405).
- **Backup** (`src/server/backup.ts`, `/settings/export`, principal only): every business table as JSON, or one table as CSV, read under the principal's session. Columns matching `_enc(rypted)?`, `search` and `embedding` are dropped; `document_chunks`, `briefings` and agent threads/messages are left out. Each export calls `log_export()`. The audit log already shows ciphertext as `[redacted]`.
- **Accessibility:** `e2e/a11y.spec.ts` runs axe (WCAG 2.1 A/AA) on every main page, the portal and login, in both themes, and must stay at zero.
  - Status colours (`--success/--warning/--danger/--info`) are per theme and reach at least 4.6:1 on surfaces and on their own 10–15% tints. Use `bg-danger-solid` (not `bg-danger`) behind white text.
  - URL-driven tabs with no `TabsContent` take `panelless`.
  - Relative times in client components go through `<RelativeTime ts>`, which suppresses the minute-boundary hydration mismatch.
- **Shell weight:** the command palette, agent panel and task editor are `next/dynamic` and mount on first use (`?task=` mounts the task editor). Don't import `@/lib/schemas/*` from always-mounted shell components: it pulls Zod into every page.

## Decisions log
- Next.js 16 instead of 15 (15 is backport-only). Approved.
- Single-tenant (one company), not multi-tenant.
- `activity_events` (sanitized, RLS-scoped) feeds Realtime. The raw `audit_log` is principal-only and never streamed.
- The introductions ledger is append-only with a sha256 hash chain. Demo and real rows chain separately so the demo wipe leaves the real chain verifiable. Corrections are new rows with `corrects_id`.
- The attention queue is a live SQL view, not a nightly snapshot.
- KPI sparklines are rebuilt from history (stage history, task completion, dated transactions) instead of a `kpi_snapshots` table, so they respect RLS per viewer. Known approximation: ticket-size edits aren't versioned.
- Monthly burn is visible to managers in aggregate (payroll included). Individual payroll rows and bank balances are principal-only.
- Compliance items are seeded as `unconfirmed` and only surface as "confirm whether this applies". Nothing drives alerts until a principal confirms it.
- The Faminas mandate names DIFC-LCIA as forum. That centre was abolished by Dubai Decree No. 34 of 2021 (cases moved to DIAC). This is flagged in the contract notes for counsel.
- Embeddings: Supabase built-in `gte-small` (free), via the `embed` edge function, which also requires role `authenticated` because the gateway accepts the public anon key. OCR: Claude only for files with no text layer. Search is hybrid (full text + vectors, reciprocal rank fusion) over the current version only, with title matches as a fallback.
- No service-role key on the public share page: a time-boxed anon storage policy instead (see Conventions).
- Only watermarkable formats (PDF, PNG, JPEG) can be shared externally. Word files must be exported to PDF first.
- Share links last at most 30 days (the database allows 31), can be shortened or revoked, never extended or re-pointed.
- The salary certificate is principal-only and prints only figures from the employee's latest **paid** payroll run (`salary_certificate_data`); nothing about pay is typed into the form, and Ask Lantana can't generate it. Invoices print only from recorded invoices; amounts are never typed into the template. Bank details are never printed on invoices.
- Template wording defaults disputes to DIAC arbitration and every generated file is saved as a draft for counsel. Contracts whose forum names DIFC-LCIA get a flag on the register.
- A new contract's owner defaults to whoever adds it, so alerts and obligation tasks always reach someone.
- The morning briefing is written on the reader's first Command Center visit of the Dubai day, not by a 07:30 cron: it runs under the reader's own JWT (no service-role key, never shows what they can't see), costs nothing on days nobody opens the app, and is cached in `briefings`. The rule-based lines show instantly and whenever there's no API key. The model gets only facts computed by `briefingFacts()` (`src/lib/briefing-facts.ts`).
- The nightly scan, expiry alerts and Monday digest are SQL functions on pg_cron (no Edge Functions, no AI): they only write notifications.
- Clause review compares the contract's linked document with Lantana's own template (NCNDA, mandate, engagement letter) using structured output, saves the findings on the contract, and says it isn't legal advice.
- Closing a deal (won/lost) requires a reason; `move_deal_stage()` writes it onto the stage-history row.
- The investor matcher is deliberately simple and explainable: sector 40, geography 30, ticket 30, with the reasons returned.
- Introductions chain verification is `SECURITY DEFINER` and manager+ only, because it must read rows staff can't see.
- A task can't be marked done while a task it depends on is open (enforced in `src/server/tasks.ts`).
- Tasks only have due dates, so the timeline shows task dots, not bars. We don't invent start dates.
- Principals are employees with `on_payroll = false` (paid outside payroll), so payroll runs don't list them as missing a salary.
- Payroll pro-rates by calendar days for joiners and leavers, takes the salary in force on the month's last day, and is AED-only (WPS is AED).
- The WPS SIF layout (EDR lines + SCR control line, file `<employer id><YYMMDDHHMMSS>.SIF`) follows the common CBUAE format; the UI tells the user to confirm it with their bank or exchange house before the first submission. Missing numbers produce a list of what to add, never a partial file.
- Gratuity is an estimate under Federal Decree-Law 33/2021 art. 51 (21 days' basic per year for five years, 30 after, pro rata, nothing before a year, capped at two years' pay); it doesn't deduct unpaid leave.
- Category suggestions on import are rules + history (free, explainable). The person still confirms every line; `category_source` records where the category came from.
- E-signature is a stub (`src/server/esign`): status is recorded by hand until a paid provider is approved.
- Gmail and Calendar adapters were optional in Phase 5 and are not built.
- Invite-only is enforced by the `auth.users` trigger, not by turning sign-up off, so invited guests can create their account with a magic link and no service-role key is involved.
- Data-room guests are a separate role (`external`) with a separate portal, not staff with restrictions. Only watermarkable formats go into rooms.
- Scheduled packs notify rather than email: building a report for someone else would need the service-role key. Emailing waits on an approved provider (DEPLOY.md).
- Vault copies of reports never contain cash. The PDF download may, and is audited.
- Status colours were darkened in light mode and lightened in dark mode for WCAG AA. Charts keep `--chart-in` / `--chart-out`.
